# Fault-injection matrix — local evidence 2026-08-19

## Environment and method

The final host and toolchain capture is
[`../environment/20260819-local-wsl-final.txt`](../environment/20260819-local-wsl-final.txt).
C++ black-box cases use a Debug build with warnings as errors, one normal
Worker, a local fake HTTP control plane, real signals and sockets, and explicitly
small queues where noted. Go cases use `MemoryStore` unless a test name begins
with `TestRedis`. Container and Kubernetes rows are kept pending when the local
environment cannot execute them.

The principal local command was:

```bash
cmake --build cpp-gateway/build --parallel 4
ctest --test-dir cpp-gateway/build -R graceful_shutdown_test \
  --output-on-failure --repeat until-fail:3
```

Raw outcome: all three consecutive `graceful_shutdown_test` runs passed, taking
10.15 s, 10.08 s, and 9.58 s. The complete Go/C++ release-gate outcome belongs
in the final release report; this report maps every required fault to the
smallest executable proof.

## Limits and pending evidence

The fake control plane deterministically exercises C++ network and shutdown
semantics but is not Redis. This WSL environment had no usable Docker daemon or
configured Kubernetes context, so the real Redis outage and Kubernetes rows are not marked passed.
Their scripts are part of the release gate, and `v2.0.0` must not be tagged
until their raw logs are captured in a capable environment. `/proc` fd mapping
is intentionally Linux-specific because the Gateway itself is Linux-specific.
